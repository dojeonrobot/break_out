보이드의 기록 — 섬 구역이 돌아올 때 연출 보강 요청서
작성 2026-11-02 · 대상 chapter05/index.html · 상태: 미착수(다음 작업에서 반영)

──────────────────────────────
1. 왜 고치나
──────────────────────────────
지금 섬 놀이기구가 돌아올 때(arriveFx → rideSweep)
  하늘 빛기둥 → 바닥 충격 고리 → 와이어 청사진 → 기구가 돌면서 그려짐
에서 바로 끝난다. 그려진 뒤 기구가 그냥 서 있고 주변도 그대로라 허전하다(사용자 지적).
→ "기록이 돌아와서 기구가 다시 작동한다"는 순간을 붙인다.

관련 코드
  - rideSweep(m, at)      약 6518행  SWEEP_MODE: coaster·carousel·safari=spin, harmonia=rise, ferris=wheel
  - arriveFx(ids)         약 6564행  빛기둥·고리·플래시·불꽃 + rideSweep 호출, islAnim에 tick 등록
  - updateI(now)          약 7072행  islAnim.forEach(f => f(now/1000))  ← 벽시계 시간
  - flyTo(pos, tgt, ms)   약 1911행
  - perfTier / perfTick   약 8105행  기기 성능 단계(터치 기기는 1부터)

──────────────────────────────
2. 추가할 연출 (사용자 선택: 1 + 2)
──────────────────────────────
[1] 전원 들어오기 — 그려짐이 끝난 뒤
  ① 짧은 정적(한 박자)
  ② 전구가 아래 → 위로 줄줄이 켜짐(기구 테두리·지붕선·간판)
  ③ 기구가 천천히 움직이기 시작(멈춘 상태에서 가속)
       회전목마  회전 시작 + 오르간 소리
       관람차    한 칸씩 돌기 시작
       롤러코스터 첫 열차 "덜컥" 출발(체인 소리)
       사파리    차량 출발
       하모니아  분수 켜짐
  ④ 기구별 효과음은 WebAudio 합성(SND/sfx)으로. 파일 추가하지 않음.

[2] 주변이 같이 깨어나기 — 작동 시작과 함께
  ① 기구를 중심으로 둥글게 퍼지는 파동을 따라 바닥 타일·꽃밭·가로등이 순서대로 켜짐(거리 순)
  ② 구역 이름 아치 간판 글자가 한 자씩 점등
  ③ 기구 하나가 아니라 "구역 전체가 돌아왔다"로 읽혀야 함

넣지 않는 것: 폭죽·꽃가루(흔함), 설명 문장, 일루아 수치·조각, 문양(에필로그 전 비노출),
              섬 화면에 ERICA·좌표·태블릿 언급.
보류(사용자 미선택): [3] 방문객이 기구 쪽으로 모여 대기열 채우기, [4] 기구 이름 타이틀 2초.
같이 검토할 것: 캠퍼스 건물이 돌아올 때(holeApply, 약 1248행) 회색 홀로그램 → 실제 재질이
              "딱" 바뀜 → 재질이 아래부터 차오르게. (사용자에게 아직 확정 안 받음)

──────────────────────────────
3. 시간 처리 규칙 (사용자 지적: 기기마다 사양이 달라 시간이 다르게 흐름)
──────────────────────────────
문제: 지금 연출은 시작 시각을 박아 두고 "지금 − 시작"으로 진행도를 계산한다.
      느린 노트북·태블릿에서 화면이 1~2초 멈추면, 다시 그려질 때 이미 연출이 끝나 있을 수 있다.
      (위 0.5초 같은 숫자는 "멈춤 없는 기기에서 보이는 길이"일 뿐 보장이 아님)

규칙
  (1) 연출 전용 시계: 연출마다 자기 시계를 두고 매 프레임 dt만큼 진행.
      dt는 최대 1/20초로 자름 → 느린 기기는 "느리게 재생", 단계 건너뛰기는 없음.
  (2) 단계는 시간표가 아니라 사슬: 그려짐 끝 → 전구 끝 → 작동 → 주변 점등.
      앞 단계가 화면에서 끝났을 때만 다음 시작. setTimeout으로 단계 잡지 않음.
  (3) 시작 조건: flyTo 카메라 이동이 끝나고, 실제 렌더가 2프레임 지난 뒤 시계 시작.
  (4) 셰이더 준비 먼저: rideSweep이 clippingPlanes 재질을 복제하는 순간 셰이더 컴파일로
      약한 기기가 멈추는 게 가장 큰 원인으로 추정 → 연출 시작 전에 renderer.compile(또는
      compileAsync)로 미리 컴파일하고 끝난 뒤 시계 시작.
  (5) 성능 단계(perfTier)가 높을수록 양만 줄임(불꽃 수·켜지는 전구 수·주변 점등 개수).
      순서·단계 수는 모든 기기에서 같음.
  (6) 기존 빛기둥·고리·rideSweep도 같은 시계로 옮김.

──────────────────────────────
4. 지켜야 할 기존 규칙
──────────────────────────────
  - 요소가 갑자기 "딱" 나타나지 않게 — 모든 점등·작동은 생성/가속 연출로.
  - 대사·장면·걷기 중에는 연출하지 않음(arriveFx 기존 조건 유지), 캠퍼스 화면을 섬으로 자동 전환 금지.
  - 처음엔 멈춰 있다가 나중에 움직이는 물체는 userData.dynamic 표시 필수
    (batchIsland가 정적으로 구워 버림) → 배포 전 __dbg.bakedAudit() 결과가 [] 여야 함.
  - 동작 줄이기 설정(reduce)이면 기존처럼 생략하거나 즉시 완료 상태로.
  - 진행 판정은 zoneMine(TEAM 기준), zoneDone은 표시용.

──────────────────────────────
5. 확인 방법 (배포 전)
──────────────────────────────
  - 헤드리스에서 일부러 프레임을 0.3초·1초씩 멈추게 만들고(렌더 루프에 지연 주입),
    각 단계(그려짐·전구·작동·주변 점등) 시작/끝 기록이 모두 한 번씩 찍히는지 확인.
  - 평상시·느린 프레임 두 경우 모두 단계 순서가 같아야 함.
  - __dbg.sweep(id) 처럼 연출 단독 재생 디버그 함수 추가해서 기구 5개 각각 스크린샷.
  - flow_all / resume_flow errors 빈 줄, reach_audit 고립 0·길 막힘 0, bakedAudit [].
  - 배포: 실서버·아티팩트·공유드라이브(백업 하나만)·erica-twin 재빌드 동일, 커밋.
  - 실기기(Galaxy Tab S10 FE·노트북)에서 체감 확인은 사용자.
